# activation branch

Load for the actual activation task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

First-run/setup/value completion reveals a bottleneck.
Input: Real first-value journey, eligible users/tasks, cohort limits and observed drop-off; baseline may be unknown.

## Procedure and composition

Observe useful task completion and recovery first. Remove a proved comprehension, setup, permission or value barrier through one testable hypothesis. Cover signup, onboarding, pricing/paywall/entitlement seams only when relevant; truthful value and accessible exit remain invariant.
Optional complement: signup/onboarding/paywall methods for the actual bottleneck. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

Observed friction and an activation hypothesis/spec with measurable completion.
Next context: experiment or spec after evidence and acceptance; measurement after delivery. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

More acquisition is not a cure for broken value. No invented conversion, hidden pricing or dark-pattern assumptions.
Keep partial observations and denominator/version. If events are missing, instrument/observe rather than pretending a funnel exists.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
