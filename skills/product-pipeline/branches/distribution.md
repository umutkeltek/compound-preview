# distribution branch

Load for the actual distribution task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

A launch/campaign/acquisition hypothesis names an audience and channel.
Input: Usable product/value journey, audience evidence, positioning, eligible recipients/placements and exact channel grants.

## Procedure and composition

Select a channel thesis, truthful offer and useful conversion metric. Prepare variants and channel-specific assets/copy. For outbound, read ../references/outbound.md before account or message effects. Dedupe campaigns and check suppression/cooldown/provider limits. Demand generation is not the fix for broken first value.
Optional complement: marketing/copy/SEO/email/launch methods only for the selected channel. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

Bounded campaign plan or authorized delivery evidence with recipient/channel provenance.
Next context: activation for journey friction; measurement after exposure and window maturity. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

Addresses are not send permission. No fake warm-up, identity rotation, unsolicited bulk effects or automatic publication.
Persist operation/provider IDs; reconcile ambiguous submission before retry. Stop on revoked grants or declared health thresholds.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
