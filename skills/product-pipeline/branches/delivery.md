# delivery branch

Load for the actual delivery task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

An implementation ticket/slice is ready.
Input: Accepted spec, existing work lease/scope, repository reality, dependencies and eligible execution lane.

## Procedure and composition

Implement one vertical slice under existing execute/land/verify ceremonies. Test observable behavior and realistic failure paths. Use narrow isolated changes; inspect security/data migration/dependency/performance seams as touched. Persist checkpoints and terminalize attempts, including failures.
Optional complement: language/framework/testing/security methods for the touched implementation. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

Delivered source and truthful verification receipts bound to the actual consumer.
Next context: QA and release when behavior is proved; measurement when instrumentation is wired. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

No shared-main WIP, ungoverned fallback, grant changes, binary installation or publication inferred from an offer.
Retry only bounded transient failures. Preserve partial source safely; reconcile external effects and exact execution generations before resuming.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
