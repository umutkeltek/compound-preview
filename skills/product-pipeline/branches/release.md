# release branch

Load for the actual release task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

Release/signing/privacy readiness or rollback needs preparation.
Input: Verified build, scope/changelog, platform policy, secrets references, support readiness and current grants.

## Procedure and composition

Verify packaging/signing, privacy/disclosures, telemetry, migration/rollback, listing/claims and release ownership. Use exact artifact/environment identities. Plan staged exposure and real post-release checks; distinguish preparation from submission and publication.
Optional complement: platform release/ASO/hosting methods at their actual authorized boundary. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

Release-readiness packet with exact artifact, checklist evidence and rollback/stop conditions.
Next context: distribution and measurement only when the real release state supports them. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

No automatic install, account changes, submission or publication without the corresponding current grant.
Preserve preimages/artifact identities; if exposure is ambiguous, reconcile deployed/store state before retry or rollback.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
