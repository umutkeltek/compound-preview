# ux branch

Load for the actual ux task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

A journey, interaction or first-value flow needs design.
Input: Audience task, value moment, existing states, constraints and observed friction.

## Procedure and composition

Map entry, useful completion and recovery. If structure is uncertain, compare distinct interaction or hierarchy models under a declared rubric; otherwise preserve the settled model. Include empty/error/offline/permission states, accessibility and comprehension. Test the actual task, not only visual preference.
Optional complement: first-run/onboarding methods only for activation; platform interaction guidelines at the touched seam. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

Selected journey with concrete state transitions, evidence and unresolved tradeoffs.
Next context: spec only when selection is authorized/resolved; research if evidence contradicts the need. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

A small local edit does not reopen product direction. Optional prototype tools require their actual explicit-invocation contract.
Preserve alternatives and rejection reasons; test the failed journey before iterating layout.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
