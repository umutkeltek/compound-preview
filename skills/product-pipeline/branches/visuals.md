# visuals branch

Load for the actual visuals task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

A store/campaign asset set or product visual is needed.
Input: Verified product states, channel format, audience/claim, rights, localization and source assets.

## Procedure and composition

Define one narrative and meaningful variation across the set. Use real UI for functionality claims; distinguish illustration/mockup from shipping behavior. Check composition, legibility, safe areas, export sizes, brand consistency and rights. Inspect final exported bytes at intended scale.
Optional complement: image/visual-generation or store-screenshot tools only for this output; verify their source and rights. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

Versioned asset set with source attribution, truthful claims and export/visual QA evidence.
Next context: release or distribution after asset review and channel readiness. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

Asset preparation grants no upload/publication or global device/profile changes. Never show fictional functionality as real.
Persist source/export mapping and rejected variants; regenerate only the failed asset, then recheck set consistency.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
