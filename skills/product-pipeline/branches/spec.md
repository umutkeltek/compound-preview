# spec branch

Load for the actual spec task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

A chosen product behavior must become an implementation contract.
Input: Accepted outcome/journey, constraints, domain terms, data boundaries and measurable acceptance.

## Procedure and composition

Define observable behavior and state ownership, APIs/data contracts, invariants, permissions, errors and recovery. Name required accessibility/privacy/security/localization seams. Slice by testable dependency frontier; write acceptance and explicit non-goals. Resolve blocking choices without regenerating an already accepted spec.
Optional complement: domain/API/data modeling methods at actual seams, not every technology skill. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

Accepted, falsifiable specification and independently verifiable delivery slice.
Next context: delivery only when dependencies and authority are ready. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

Do not create a second work state machine or infer acceptance from a draft. No endless speculative architecture.
Record changed requirements and their impact; revise only the contract invalidated by current evidence.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
