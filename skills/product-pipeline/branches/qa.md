# qa branch

Load for the actual qa task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

A critical journey, permission, offline behavior or launch check needs verification.
Input: Accepted behavior, real build/environment, representative data and failure fixtures.

## Procedure and composition

Exercise useful completion and recovery end to end. Test long/empty/boundary/localized data, accessibility, permission denial, slow/offline networks, interrupted operations, concurrency and device/container constraints. Inspect privacy, security, performance and billing integrity where touched. Keep deterministic regressions for mechanical failures.
Optional complement: platform/accessibility/security/performance checks appropriate to the actual surface. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

Reproducible journey/state evidence and ranked defects, not a polished demo.
Next context: delivery for a failing criterion; release only after readiness evidence is usable. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

Never mutate production customer data for a test or hide a failure behind visual polish. Passing unit tests alone are not journey proof.
Checkpoint fixture/build identity; minimize and reproduce a failure before rerunning broad checks.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
