# Select and update skills

Consumer: the lifecycle learning branch and the existing skill-authoring owner.
Popularity and public posts find candidates; they do not prove quality.

1. Locate the failure layer: source/installation, graph offer, actual loading, task result
   or product outcome. Read the canonical body and current binding before editing.
2. Record a source card: author/repository, exact revision/file, license scope and link,
   inspection date, trigger/near misses, prerequisites, output, dependencies, effects and
   evidence limits. Compare upstream revision diffs; preserve local adaptations.
3. Select one delta: adapt at an existing owner, specialize a distinct seam, reference
   an idea, or park/reject duplication, unsafe dependencies or unresolved copying rights.
   Never bulk-install a repo, its hooks, scheduler or permission templates.
4. Predeclare realistic positive and silence cases. Compare baseline/candidate with the
   same harness/model/context. Keep held-out cases untuned; use blind assessment and
   repeated trials for efficacy claims. Routing rank is not skill invocation.
5. Change the smallest owning surface under current ActionIntent/PolicyDecision. Preserve
   old bytes/citations and a rollback plan. Validate native import and actual source loading.
6. Verify the real consumer, total failure cost and useful output. Retain limitations and
   retire the superseded binding through its owner; do not create a second generic authority.

For copied/adapted upstream text or code, preserve its license/notices and state modifications.
A link alone is not compliance. Unlicensed sources permit no assumption of copying rights.
This bundle uses original procedures and conceptual references, not vendored upstream bodies.

See [source catalog](../SOURCES.md). Missing tools/evaluations must be reported, not fabricated.
