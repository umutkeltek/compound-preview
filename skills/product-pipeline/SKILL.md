# Product pipeline

Select the next product outcome, not every skill. This is an original Compound procedure,
informed by the [credited sources](SOURCES.md). It prepares existing work, policy and receipt
consumers; it is not a scheduler, account grant or second work state machine.

## Locate the constraint

Read the current product contract, release state, telemetry and standing grants from their
actual owners. Verify claims against source/output. Name one outcome, primary metric,
denominator, baseline, observation window and guardrails. When baseline is unknown,
select bounded observation rather than inventing an intervention benefit. Unreleased
products can measure first-value completion and release readiness before revenue/retention.

## Compose generic to specific

Use the [lifecycle map](README.md#lifecycle-map) to select one branch, then add only the
touched platform, product and channel complements. A specialization retains the generic
outcome and authority contract. Check the actual installation/source before loading an
optional upstream skill. A graph offer is not invocation; a route target is context,
not a worker address or successful handoff.

Record event/entity/revision, dedupe key, fresh inputs, readiness, one output/consumer,
existing work/ActionIntent/PolicyDecision/receipt owners, metric/falsifier, next or stop
event, attempt/time/cost/concurrency/cooldown bounds and recovery checkpoint. Repeated
cadence checks readiness; it does not authorize repeated change. Use the
[design template](examples/loop.example.yaml), which is not an executable schema.

## Explore when uncertainty warrants it

For material structure, positioning or visual uncertainty, produce two or three genuinely
different contextual candidates. Change an interaction model, hierarchy, audience thesis
or visual direction—not just colors. Predeclare a task-specific rubric; select a coherent
base and document selective grafts only under the actual product envelope. Otherwise leave
reviewable alternatives and the unresolved choice. A settled small edit stays in its design
system. Bound exploration and retain rejection reasons; judge preference is not conversion.

## Execute one bounded branch

Read its linked contract before acting. Use existing Compound work and execution ceremonies
with a narrow scope and falsifiable predicate. Choose the cheapest currently eligible lane;
compatibility metadata does not prove provider readiness. MiniMax or other lanes require
fresh served routing/capacity authority, not a remembered roster.

Persist recoverable progress and terminalize every execution attempt. Retry transient
failures inside declared bounds; missing authority or permanent failure stops that branch.
Reconcile ambiguous external timeouts using durable operation/provider evidence before retry.
For communication/account work read [outbound operations](references/outbound.md); drafting,
sending, publication and spending have distinct grants. Do not ask again for covered effects.

## Measure and improve

Record actual skill loading, state/output delta and total cost including failures. Observe
consumption by the real product/review owner. Separate source quality, selection, invocation,
task success and business outcome. Sparse or immature evidence stays inconclusive.

Route repeated mechanical failures to deterministic checks; update useful judgment through
the [selection/update procedure](references/skill-selection.md). External discoveries remain
source evidence until governed adjudication. Do not self-promote a skill after one success.

Return the constraint, selected branch/complements, actual inputs and proof, unmeasured
outcomes and next bounded move. A retrievable map alone is not autonomous execution.
