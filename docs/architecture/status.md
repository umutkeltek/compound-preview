## Commands

External repo intake surface note: `capability external-intake --source-list <file>` keeps aggregate/source-list counts plus bounded next-action queues in human output and omits known row details behind `--json`, so large repo lists stay operator-readable without losing evidence. Default `capability external-intake` separates raw `keep_needs_review` classification from actual `open_owner_reviews`, and high-value rows show owner-review, capability-evaluation, and graph status instead of calling recorded/imported rows review-next work. `external-intake-import-reviewed --source-list <file>` explicitly imports reviewed manifests into CapabilityGraph authority; `needs_review` nodes remain non-surfacing, so imported does not mean served/adopted.

Dispatch read-model status note: Workbench resolves recorded dispatch-step waits to `status=resolved` / `wait_reason=terminal_work` when every blocked work ref is already terminal, and resolves historical `no_open_work` waits as no-op summaries, without rewriting old run files; operator orient hides resolved/no-op dispatch history from the RUNNING triptych.

Distiller request record note: `distiller request --record` artifacts under `reviews/distiller-requests` annotate the review queue as recorded replay packets with source refs, not human review debt; invalid request JSON remains blocked.

Hook input hash note: context-producing hooks hash normalized hook, harness, cwd, task, repo-kind, mode, and prompt digest, so same prompt/task in different scope does not collide and raw prompt text stays out of artifacts.

Hook readiness authority note: `compound contract hooks-authority` reports `hook_readiness[]` from installed-hook authority, fixture coverage, and `--live` adapter support; `--observe-live` keeps desired `hook_plan`, read-only `installation_observation`, and deterministic `reconciliation` separate, so observed extras never become desired truth. Reconciliation `registered` means the active invocation matches while handler-content bytes remain unverified; reconciliation `ready` requires matching desired/observed handler-content revisions. hook-readiness-action-contract guard: Codex SessionStart/UserPromptSubmit/PreToolUse are `ready` when their adapters are present; default interactive Codex PreToolUse is observational and must not report `native_blocking` or emit a native permission decision. `native_blocking` is reserved for an explicitly blocking binding installed with `--enforce`; `codex-pretooluse-native-gate-proof` exercises that opt-in path with valid `apply_patch` allow plus mixed-target `permissionDecision=deny`. Missing live adapters still expose `prove_fixture_hook`, `expected_exit_code`, and operator-only `operator_live_adapter_required` through `compound contract hooks-authority`, EffectiveContract, and ContextPack before any registration flip.

Hook context side-effect note: context-producing hooks list the full persisted artifact chain in `HookEvent.side_effects`: redacted request, dated EffectiveContract, ContextPack, and harness-facing injection markdown; `output_ref` points directly at injection markdown, whose `Capability Offers` section renders surfaced offer refs/names/constraints before budgeted provenance/decision lists while full refs remain in ContextPack JSON.

Distiller runtime-source note: `distiller.LoadRuntimeSources` follows safe relative JSON `HookEvent.side_effects`, validates typed envelopes, dedupes already-loaded work/context artifacts, includes ContextRequest/EffectiveContract envelopes as grounded extraction sources, preserves HookEvent `output_ref` in structured LLM envelopes, and includes output refs in request `source_refs` so grounded extraction can cite them.

Active packet proof note: `work active-packet-proof --source-packet <packet.md>` and `workbench --source-packet <packet.md>` compare the current packet evidence ref against the proof chain, so stale terminal packet proof reports risk instead of `source_packet_terminal`.

CLI safety note: `compound capability ... --help`, plus guarded `work`, `memory`, and `route cost-doctor` subcommand help paths, return usage before opening runtime state, so help requests cannot consume receipts, import graph data, validate work/memory fields, or open provider ledgers.

Contract command status note: `compound contract compile`, `compound orient`, and hook context injection all materialize one shared runtime snapshot, bind one descriptor-backed installed-entrypoint revision into both artifacts, seal exact bodies to immutable 16-hex content-bound `contract_*`/`ctx_*` ids, and persist the caller-visible sealed pair through `RecordRuntimeMaterialization`, which refuses request-shaped ids; dated EffectiveContracts and ContextPacks are immutable proof refs while `contracts/effective/latest.json` is only the mutable current projection. Compile preserves its EffectiveContract stdout JSON; `--instructions` renders the compiler-owned stable block for the harness's tracked static surface and `--check-instructions` exits non-zero on managed-block drift, while task intent/memory/capability/check bodies remain ContextPack-only. `compound mcp-transport` is the public stdio MCP entrypoint: lifecycle clients use exact supported-version negotiation and `initialize` → `notifications/initialized`, while modern clients use `server/discover` plus per-request protocol/capability metadata for stateless `tools/list` and `tools/call`. Stateless removes the session-lifecycle dependency; it does not make either tool read-only. `compound_finding_record` writes private operational evidence (including refs) through `internal/finding`, while `compound_orient_recall` writes the sealed EffectiveContract, mutable latest projection, and ContextPack through the existing orient materializer; neither path promotes or adjudicates memory.

ContextPack hook status note: task-oriented runtime packs project the existing bounded breadth-dependency trace into optional `retrieval` metadata before sealing: `used|degraded|refused|not_attempted`, fixed `compound_ledger` authority, and `ledger_ranker` fallback for every non-used outcome. Legacy omission remains valid. Requested/observed engines are bounded slugs; `not_attempted` may preserve only the requested engine, never an observed engine or error class. Failures use only the existing error classes; no raw provider error, query/task/body, endpoint, credential, request/response, or retry data can enter this object. This is observability over the one existing ledger-gated ranking path—not a second retriever, retry loop, provider policy, or hook prose—and the content-bound ContextPack id covers the exact posture. Active hook refs appear in both `active_hooks`/`hook_roster` and `included[]` with runtime/current reasons, while task-excluded hooks remain in `excluded[]`; mutation contexts with adapter-required write-gate readiness add `required_checks[]`, so consumers see the enforce command before writes.

Hook context mode status note: hook context artifacts use one requested-mode decision for both `ContextRequest.requested_mode` and `EffectiveContract.task_mode`: `session-start` orients in `observe`, while `user-prompt-submit` creates execute-mode proposed work context.

Hook event identity note: `HookEvent` IDs include the normalized input hash, so same-second hook runs with different task/prompt/action inputs do not overwrite persisted hook events or context injection artifacts.

Receipt consumer status note: `Receipt.EffectiveChanged` is the read/consume rule for Workbench, operator orient, and CapabilityGraph receipt mining; completed proof-bearing non-`audit_only` receipts count changed even if an older receipt stored `state_delta.changed=false`; Workbench recent items surface `Receipt.proof_refs[]` as `evidence_refs[]`, and operator orient changed/recent rows carry those Workbench evidence refs so receipt-only proof chains remain operator-visible.

Work command status note: `work create-plan` emits a create command with planned `--work-id` and envelope fields; `work create --work-id` preserves that root id through admission before lifecycle write. `work close` treats completed proof-bearing non-`audit_only` moves as changed receipt deltas even when the closer omits `--changed`, so Workbench/operator tags and receipt mining do not mislabel landed deltas as unchanged; `work close` also rejects unknown flags before terminal write and accepts repeated `--proof-ref` values in addition to CSV `--proof`, preventing typoed proof refs from silently dropping receipt evidence.

Workbench capability surface note: `workbench --capability-task ...` embeds a bounded operator offer window (`offer_limit`, `omitted_offer_count`) while preserving full `offer_count`; exhaustive surfacing remains `capability surface`.

Work dispatch status note: `work dispatch-claim` attaches a capability-only worker ContextPack with explicit work/capability source revisions and an excluded contract marker rather than pretending a fresh EffectiveContract was compiled. `work dispatch-execute <work_id>` is the bounded selector consumer: preview is read-only; confirmed execution derives one capability resolution from the WorkEnvelope, chooses the first eligible adapter-backed route without caller actor/harness/model flags, validates workspace and roster and runs the selected adapter's preflight before claim when it exposes one, then reuses the governed executor to reach `verifying` or `failed` and records route authority on its terminal RunAttempt. It is explicit one-shot execution, not a scheduler or daemon.

Work ContextPack status note: Work admission/import/advance validate any supplied `context_pack_id` resolves to a recorded `COMPOUND_HOME/context/packs/<id>.json` artifact and any declared `contract_id` resolves to a matching validated `contracts/effective/<date>/<id>.json` artifact before persisting lifecycle mutation.

Spine orientation note: `compound orient --operator [--json]` is the compact operator projection over needs-me/running/changed. It reads candidate inboxes, shared review queue, workbench open/recent state, receipts/transitions, and the memory claim ledger, with only a rebuildable `projections/orient-operator-last-seq.json` cursor write for claim-seq deltas. Candidate totals keep raw backlog visible, while `candidate_actionable`, per-inbox `actionable_count`, readiness counts from `state`/`status`/`verdict` plus `promote_allowed=false`, and `oldest_actionable_item` keep parked/promoted/rejected/no-promote migrated candidates from looking like current operator debt.
