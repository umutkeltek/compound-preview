# Epistemics Contract

**Binding autonomy status.** The `job_health` path below is implemented but
bench-only. Imported, generic, fixture, and legacy route rows remain review
evidence and cannot decide; no production caller currently mints
`trusted_panel_runtime`. A qualifying terminal event seals canonical hashes
for one WorkEnvelope and exactly one Receipt, with exactly one well-formed
`director_trigger:<class>:<identity>`. Eligibility `generated_at` must
equal the admission instant, so earlier artifacts are audit evidence rather
than reusable authority. Finally, `operator:*`/`human:*` is currently
caller-supplied provenance, not authenticated OS/user identity. Protected
record shape prevents generic-memory shadowing but does not make rented
executors safe grant minters.

Compound treats epistemic doctrine as an enforced contract, not ambient prose. The rows below are deliberately machine-parseable by `compound architecture doctor --strict`: each principle names the existing implementing object family and at least one CLI verb that proves the branch is observable.

**Suggested-work boundary.** The director organ (`internal/director`, driven only by `compound director propose`) is the system's highest drift risk — the place a suggestion engine could quietly grow into a scheduler or boss. Its boundary is therefore stated and enforced explicitly, not assumed. A director run has **no background or scheduler mode** (one synchronous `Propose()` call, no goroutines, timers, process exec, claim, run, or task command); does **no auto-continue** and takes **no external side effects**; performs **no memory promotion** and **no policy edits**; caps output at **max 5 proposals per run**; **requires evidence refs** on every proposal; and applies duplicate suppression. Non-`job_health` classes remain create-plan previews requiring operator admission. For `job_health` only, `--apply` may materialize the content-sealed create plan as `proposed` and call the sole `AdmitAuto` seam; admission succeeds only when a current operator decision record has explicit class/sample/window/failure thresholds and a content-addressed eligibility artifact replays the latest terminal Receipts, genuine state deltas after routing-only refs are removed, exact work-bound deciding route rows, current route-plan identity/router revision, and the actual resolved model/provider identity mapped to a current `GateRole=eligible` lane. Requested route aliases never substitute for resolved identity. Models and harnesses produce evidence; this deterministic gate decides sufficiency. The accepted autonomy ruling contains no numeric threshold and therefore activates nothing by itself. A broad `director-apply` grant still authorizes filing only; it is never autonomy authority.

Admission precedence is fixed: **global/per-class halt → editable surface → freeze → non-overridable operator-only risk → typed eligibility**. `external_side_effect`, `public`, `destructive`, `financial`, and `security` mutation classes; `irreversible`, `hard`, and `none` reversibility; and wide blast radii can never auto-admit, even under an ordinary standing policy grant. Assumed/supervised-only, unknown-claim, unknown-tier, free tripwire, and resolution-undeclared judge lanes can contribute evidence but cannot decide. The canonical work creation/action/lifecycle/archive, halt, operational-decision, editable-surface, operator-state, standing-grant, route-evidence, and router writers share the `$COMPOUND_HOME/lock/autonomy-admission.lock` advisory lock, so final revalidation and proposed→admitted commit have one serializable order; concurrent attempts commit exactly once and stale create plans cannot overwrite newer state. Operational `grant`, `freeze`, and `ruling` promotion is reserved to the operator-provenance policy-decision importer; ordinary policy/doctrine imports never receive its stamp. Runtime reads also require explicit operator/human provenance, so pre-fix stamped executor claims remain audit history but hold no authority. Runtime controls fold protected decision history independently of generic MVCC supersession and review edges, and ordinary adjudication refuses copied stamps, operational kinds, and protected same-ID slots, so matching qualifier strings never turn extracted meaning into authority or hide a real revocation. The narrow pre-stamp shape remains supported only when its `reviewed_by` has explicit operator/human provenance. Each recent terminal lifecycle event seals the canonical WorkEnvelope hash; exactly one event and one matching hot/restored/archived snapshot must exist. A class-relevant terminal snapshot with no terminal event fails closed before lookback filtering, and neither terminal-event nor Receipt time may exceed the proof's frozen evaluation instant. Archive index/hash/path/status drift or repeated active archive rows also fail closed. Operators change the emergency switch through `compound policy autonomy-halt --global --reason <text>` / `--clear-global` / `--disable-class` / `--enable-class`; direct edits to its YAML projection are unsupported because they bypass that order. Manual edits to `policy.yaml` or `editable-surfaces.yaml` while autonomy is available are likewise unsupported: engage the global halt, edit and validate, then clear the halt through its locked command. Successful admission persists the exact grant/claim, eligibility, threshold, Receipt, route-plan, route-evidence, resolved provider/model, and router-revision refs on both the WorkEnvelope and the proposed→admitted event. This changes admission only: it adds no Director verb, scheduler, claim, execution, owner mutation, provider change, or real grant. User-facing surfaces still say "suggested work"; "director" remains an internal package name. Boundary, threshold, tamper, revocation, concurrency, and precedence tests under `internal/director`, `internal/work`, `internal/routeevidence`, `internal/home`, and `internal/policy`, plus CLI-surface tests, enforce the invariant.

**Autonomy creation and clock seal.** Work carrying Director-proposal markers (`proposed_by:director` / `director_trigger:*`) can be created only in `proposed`; `admitted`, `ready`, and every later state require the governed lifecycle seam. The Director apply-run receipt is bookkeeping (`director_run:*`), not a proposal, and follows the ordinary ready → claim → run → close path. The public create/create-plan/import-packet CLI accepts only `proposed|ready` initially. For an autonomy sample, the sealed terminal event and its Receipt must resolve to the same normalized instant; disagreement, backdating, or a timestamp after the frozen evaluation fails closed before cohort filtering or ordering.

**Editable-surfaces boundary (EVOLVE-BLOCK).** The kill-switch answers "may the system admit ANY autonomous work now?"; a sibling **editable-surfaces registry** (`internal/policy/editable_surfaces.go`, live-loaded from `$COMPOUND_HOME/config/editable-surfaces.yaml`, surfaced by `compound policy editable-surfaces --json`) answers "for a system-originated proposal that declares a `target_surface`, is THAT surface one the operator has explicitly, actively opened for edits?". It is fail-closed: an absent, empty, or invalid registry makes **nothing** editable, and a compiled-in HARD-DENY core — `policy`, `permissions`, `ledger`, `evaluator` — can never be whitelisted (listing one is a loud validation error that invalidates the whole registry), so the evaluator and the policy/permission/ledger spine stay outside any loop that could edit them. Enforcement runs at the same admission seam the kill-switch guards (`internal/work` `AdmitAuto` + the generic `Advance` seam), AFTER the halt check so a halt always wins; a proposal without a `target_surface` is ordinary work and is unaffected. Guarded by `internal/policy` and `internal/work` falsifier tests (hard-deny core, absent/active/retired lifecycle, halt-wins).

Known open gaps stay packet-sized: expectation claims outside product loops belong to the EffectiveContract stage; directional generic/specific recall belongs to the directional graph packet; full scope lattice content belongs to the later scope-lattice work. These are not separate doctrine engines.

The matching importable CapabilityGraph doctrine nodes live in `fixtures/skills/epistemics-doctrine.yaml`. They use the existing `compound.skill_manifest.v0.1` adapter and `kind: doctrine`, so they can enter the graph through the same reviewed capability import path as other capability rows.

### Addressed-work recall scope

An explicit Work address is an opaque retrieval anchor; its identifier fragments
do not request product or system topics. For an addressed-work query, another
subject's operational status needs a matching current-workspace or named subject,
an exact target Work reference in meaning/provenance, a semantic signal, or
explicitly selected topic scope. A configured default probe contract also supplies
deliberate scope; a built-in classifier matching a generic task word does not.
The same eligibility check runs before a probe's base rank can admit a status.

This narrows context selection, never marks the status false, stale, or retired.
Reusable facts, constraints and preferences retain their lexical eligibility.
Ordinary queries, semantic scores, and visibility/policy gates retain their existing
behavior. Withheld positions retain existing identity/topic-only omission handling:
the fold does not carry the visibility/canon fields needed for a new typed decision.
Opaque Work fragments cannot manufacture that topic match. Explicit topic inspection
and historical ledger drilldown remain available.
